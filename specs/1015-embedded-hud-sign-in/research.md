# Existing authority boundaries

Convergence authenticates configured users with bcrypt and issues a 24-hour JWT. Its current middleware uses role and sites from the JWT, or accepts a separate configured machine credential. The incident routes check role and site, and the security disposition records the user subject. The existing JWT has no per-session revocation lookup. Embedded operations need a separately revocable user grant and a current user lookup. [Login](../../ui/convergence-api/src/routes/auth.js) · [Bearer authentication](../../ui/convergence-api/src/middleware/auth.js) · [Case disposition](../../ui/convergence-api/src/routes/incident-actions.js)

NetClaw owns an installation-bound session cookie and a private binding store. It already checks local access and revalidates the installation before returning retained-evidence reads. Its browser extension proposal introduces dashboard navigation. An authenticated server integration needs its own host review. The proposed service interface should expose the verified owner and lifecycle through a supported hook. Sharing the binding database or trusting a forwarded owner header would tie access to an undocumented implementation. [NetClaw browser extension proposal](https://github.com/automateyournetwork/netclaw/pull/356)

The two servers have distinct responsibilities. Convergence must be able to revoke its grants, resolve current roles and sites, authorize case operations and record the actor. The HUD backend must be able to reject a stale or ineligible HUD session before dispatch and before returning private data. Neither the HUD's local profile nor its browser extension can stand in for a signed-in Convergence user.
